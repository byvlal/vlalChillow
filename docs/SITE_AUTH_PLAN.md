## 2. Решения (подтверждены тобой)

| Вопрос | Решение |
|---|---|
| Кому строка онлайна | **Только вошедшему**, в его персональной строке. Список составом из чата убираем совсем; уже существующие одиночные «`<ник>` Подключился!/Отключился!» остаются |
| Сколько живёт сессия | **До рестарта сервера, без TTL.** Рестарт гасит все сессии и коды |
| Аватар | **Показываем**: по захватам это настоящий JPEG — отдаём байты как `image/jpeg` |
| «Завершить игру» | **Завершить катку с итогами**, per-room: `C2=201` FinalHud по текущему счёту → 5 с → `C2=255` → закрытие комнаты |
| Полный состав лобби | **Убрать совсем**: автоматических рассылок нет ни при каких событиях, команды-печати тоже не будет. Только счётчики онлайна |
| «Завершить игру» до начала катки | **Всегда с итогами**: даже в `WaitingPlayers`/`Warmup` показываем FinalHud с текущим счётом (0:0), затем teardown |
| Проверка бана на сайте | **По ID игрока**: `PlayerDirectory.Resolve(id)` → ник + все известные IP → `BanRegistry.Inspect(nick/ip)`. Тот же механизм, что в лобби, только ключ на входе — ID |
| Ротация кода каждые 30 мин | **Без спама в чат**: новый код — при следующем входе в лобби или по команде (`/code`) |

Остальные мои дефолты (правим, если что-то не так):

1. **Код привязан к серверному ID** (`MatchPublicId.ForNick(nick)`), а не к нику: ID — та же производная от ника, что в строке «ID:» и в катке (`uid`). Хранилище: `id → (code, issuedUtc, expiresUtc, nick, avatar)`. **Один активный код на игрока**: выдача нового мгновенно убивает старый.
2. **Коды и сессии только в памяти.** Рестарт = всё мертво. На диск не пишем.
3. **Где выдаётся:** в персональной строке при входе в лобби:
   «Ты `<ник>` · ID: `<id>` · код: `<123456>` · онлайн 7 (в матче 4)» + подсказка «код для сайта, живёт 30 минут».
4. **Что убивает код:** дисконнект лобби (статус не `InMatch`) — мгновенно; переход в катку и выход из катки — **не убивает** («перезашёл именно в лобби», как в issue).
5. **Сессия:** обмен кода на cookie `sc_session` (случайный токен, `HttpOnly`, `SameSite=Lax`, `Path=<basePath>`; `Secure` — по конфигу, т.к. по LAN сайт открывают по http). В памяти: `token → (playerId, nick, issued, lastSeen)`. **Ротация кода и перезаход в лобби сессию не убивают.**
6. **Авторизованные = только мутирующие запросы:** `POST /api/rooms`, `POST /api/rooms/{n}/end`. Чтение (`/api/status`, `/api/rooms`, `/api/modes`, страница) остаётся публичным.
7. **Баны для веба — по ID.** Новый мелкий класс в слое банов (без сокетов и без провода):
   `IsBannedById(id)` = `PlayerDirectory.Resolve(id)` → `SeenPlayer { Nick, Ips }` →
   `BanRegistry.Inspect(new BanProbe(nick, ip))` для ника и каждого известного IP.
   По ID видно и ник, и все адреса человека — ровно как ты сказал. Веб получает это одним
   колбэком `Func<int, bool>`; admins по-прежнему освобождены (тот же `isAdmin`-колбэк).
   Проверка: при обмене кода (отказ «аккаунт забанен») и **на каждом** авторизованном запросе
   (403 + сессия слетает). Лобби-вход забаненных уже отклоняется существующим `InspectBan` —
   его не трогаем.
8. **Перебор кодов:** 6 цифр = 10⁶. Лимиты через существующий `WebRateLimiter`: N попыток с IP в окне → блок.
9. **Аватар на сайте:** `GET /api/avatar` (или `/api/avatar/{id}`) отдаёт байты из лобби с `Content-Type: image/jpeg` и `Cache-Control: private, max-age=300`. Нет аватара (клиент прислал `hasAvatar = 0`, как пробник в `chat.zip`) → заглушка с инициалами.
10. **Если катка в комнате ещё не началась** (фаза `WaitingPlayers`/`Warmup`, раундов не было) — итогов показывать нечего: закрываем комнату без FinalHud. *(вопрос 2 ниже)*

## 5. Доказательства (разведка сделана)

**Аватар — JPEG.** Распарсил захват входа в лобби реального телефона из репо
(`captures/chat.zip` → `20261114_044418_002_client_op3_len41865.bin`, JoinResponse от хоста-телефона),
парсер по `LobbyCodec.ParseJoinSnapshot`/`ParseMember` (`BinaryIo`: varint-строки, LE-числа):

```
lobby='一加 13' selfId=3 members=3
  id=0 name='влал'           avatar=yes len=11042  JPEG 256x256
  id=1 name='FinalSapper78'  avatar=yes len=15141  JPEG 256x256
  id=2 name='влал2'          avatar=yes len=15517  JPEG 256x256
```

Проверка целостности: `FFD8` … `JFIF(APP0)` → `DQT` → `SOF0 256×256, 3 компонента` → `DHT`
→ `SOS` → `FFD9`. Все три файла проходят полный обход сегментов, обрывов нет.
Итого: поле `avatar` в лобби — готовый JPEG, его можно отдавать браузеру как есть.
(В `captures.zip` — те же люди, те же 11–15.5 КБ; у пробника `--client` стоит `hasAvatar = 0`.)

Остаётся проверить тестом (не доказательство, а регрессия): переход лобби→катка и возврат
из катки код **не** убивают, дисконнект из лобби — убивает (ориентир: `wasInMatch`,
`GameNetHost.cs:145`).

## 7. Чего точно не делаем

- Ни одного нового опкода/поля/тайминга на UDP. Всё общение с игроком — существующий
  server-чат. Досрочный конец комнаты использует **уже существующие** `C2=201` + `C2=255`.
- Не трогаем матч-провод, баны как механизм, discovery, плагины.
- Коды и сессии — только в памяти; ничего из `captures/` / `logs/` не коммитим.
- Не угадываем неизвестное: если что-то не подтверждено доказательствами — заглушка + честный лог.
- Не растим god-файлы: `WebPanelRouter` (400) и `WebPanelHost` (429) расширяются только через
  новые partial/классы; `index.html` (1300 строк) при необходимости распилить на отдельные
  embedded-ресурсы (JS/CSS).

## 8. Все вопросы решены — план готов к реализации

Открытых вопросов не осталось. Мелочи, которые беру на себя (скажи, если не так):

1. **Текст отказа на сайте** — по формулировке из issue: «код не существует или неактивен,
   перепроверьте правильно ли написан или перезайдите в лобби для получения нового кода».
2. **Лимиты перебора:** 5 неудачных обменов кода с IP за 10 мин → блок на 60 с (поверх
   существующего `WebRateLimiter`, те же числа, что у отказов панели).
3. **Cookie:** `sc_session`, случайный токен (256 бит, base64url), `HttpOnly`, `SameSite=Lax`,
   `Path=<basePath>`, `Secure` — только если `web.secureCookies = true` (по LAN сайт по http).
4. **Коды:** 6 цифр, случайные, без исключений по «красивым» номерам (10⁶ пространства при
   лимитах выше достаточно).
5. **`/ids`, `status`, дашборд** коды не показывают (код — личный, только самому игроку в чат).
6. **Админских действий с сайта не делаем** — issue их не просит.

## 9. Порядок работы после подтверждения

`A → B → C → D → E → F → G → H`, каждый шаг отдельным коммитом (не PR — ветка одна,
PR откроем один в конце, либо по твоей команде на каждый шаг). После каждого шага:
`dotnet build -c Release` + `dotnet test -c Release` + `dotnet format --severity warn`.

**Кода пока нет ни строчки — жду подтверждения.**
