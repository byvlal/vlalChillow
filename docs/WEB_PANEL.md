# Веб-панель комнат

Панель — это часть того же исполняемого файла, что и сервер. Отдельного бинарника,
отдельного конфига и отдельного порта для игры нет: комнаты мультиплексируются на одном
игровом сокете, а панель лишь читает их состояние и умеет создать комнату.

```
игрок ──браузер──> nginx ──> 127.0.0.1:8080  (панель, TCP)
игрок ──игра────> UDP 7777   (матч,   НЕ меняется)
игрок ──игра────> UDP 7778   (лобби,   НЕ меняется)
игрок ──игра────> UDP 5056   (discovery, НЕ меняется)
```

## Что умеет

| Действие | Как |
|---|---|
| Посмотреть, кто онлайн | Открыть страницу |
| Войти | Код из лобби: «Ты `<ник>` · ID: … · код: 123456» (команда `/code` — новый) |
| Посмотреть комнаты | Вкладка «Публичные комнаты», фильтры по режиму и карте |
| Создать комнату | Одна кнопка: режим, карта, имя — но только после входа |
| Посмотреть счёт | В строке комнаты: счёт `CT * T` (например `5 * 3`) |
| Позвать друзей | Кнопка «скопировать» даёт `/join 2v2 #3` |
| Зайти в комнату | «Войти» у комнаты: окно с командой `/join 2v2 #3`, уже в буфере обмена |
| Завершить свою катку | Кнопка «Завершить игру» у «Моей комнаты» (она всегда сверху) |
| Пожаловаться на игрока | `#/reports`: поиск по ID, подтверждение ника, причина; нужен вход |
| Посмотреть администрацию | `#/administration`: все из `admin.ids`, ник ведёт в профиль |
| Открыть публичный профиль | `#/player/<id>`: ник, `[ADM]`, статистика, счётчик жалоб |

Создание комнаты возможно **только** с сайта. Команд вида `/create` в игре нет и не
будет: кнопка — это единственный вход.

### Вход по коду (#51)

Комната создаётся за конкретным игроком, поэтому сайт должен знать, кто перед ним:

- при входе в лобби сервер выдаёт игроку **6-значный код** — в той же строке чата,
  где его ник и ID;
- код живёт **30 минут**, потом перестаёт действовать; новый — командой `/code`
  в чате лобби или при следующем входе;
- вышел из лобби — код протух сразу; ушёл в катку и вернулся — нет;
- код меняется на сессию сайта (кука `sc_session`), и она действует **до
  перезапуска сервера**; перезапуск гасит все сессии и все коды — вход заново;
- без сессии сайт не принимает ничего, что меняет состояние: создание комнаты и
  завершение катки отвечают `401`.

Ник, ID и аватарка на странице — из лобби (сервер отдаёт ровно те байты аватара,
что прислал клиент). Забаненный аккаунт не входит: «аккаунт забанен», а если бан
поставили, пока человек сидел на сайте, — сессия сгорает в первом же ответе `403`.

## Сайт и медиа

Сайт — один `index.html` с хэш-маршрутами (перегрузок страницы нет):

| Маршрут | Что |
|---|---|
| `#/` | главная: видео-герой, о проекте, «как начать», репорты, живой статус |
| `#/how` | главная секция «как начать» якорем |
| `#/play` | комнаты: вход по коду, создание, список |
| `#/reports` | жалобы: мастер, «мои жалобы», вкладка модерации для админа |
| `#/administration` | список администрации сервера |
| `#/player/<id>` | публичный профиль игрока (числовой или кастомный ID) |
| `#/profile` | свой профиль: статистика, кастомный ID, предупреждение о жалобах |
| `#/admin` | админ панель (после кода этого запуска) |

Видео hero, постер и шрифты раздаёт `GET /media/{имя}` (только GET). Файлы
вкомпилированы в exe из `Web/Media/`; если рядом с exe есть папка `webmedia/`,
файлы из неё имеют приоритет — можно подменить `hero.mp4` без пересборки.
Для видео поддержан `Range` (206/416): без него мобильный Safari не играет
файл до конца. Кэш: шрифты — год (`immutable`), остальное — сутки.

Примерка дизайна: адрес `/?select` показывает панель переключения заголовка,
акцента и кнопки; выбор пишется в URL (`/?select&title=2&accent=orange`).

## Настройка

В `config.json`, секция `web`:

```json
{
  "web": {
    "enabled": true,
    "bindAddress": "0.0.0.0",
    "port": 8080,
    "maxRooms": 64,
    "emptyRoomTtlSec": 600,
    "publicBaseUrl": "",
    "basePath": "",
    "secureCookies": false,
    "codeTtlSec": 1800,
    "limits": {
      "requestsPerSecond": 30,
      "refusalsBeforeBlock": 5,
      "refusalWindowSec": 10,
      "blockDurationSec": 60,
      "maxConnectionsPerIp": 8,
      "maxConnectionsTotal": 256
    }
  }
}
```

- `bindAddress` по умолчанию `0.0.0.0` — все интерфейсы: панель сразу открывается
  и с телефона в той же сети. Только свой адрес — `127.0.0.1`, если наружу её
  отдаёт один nginx на этой же машине.
- `publicBaseUrl` — адрес, который называется игроку в ответе «комната не найдена».
  Пусто — сервер определит сам (внешний IP, затем LAN). **Настоящий домен вписывается
  здесь, на машине владельца, и не попадает в репозиторий.**
- `basePath` — под путь, если панель открывается не с корня (`/vlalchillow/`): кука
  сессии ставится на этот путь, иначе браузер её не вернёт.
- `secureCookies` — `true`, когда панель открывается по https. По http — `false`
  (иначе сессия не сохраняется вовсе).
- `codeTtlSec` — сколько живёт код из лобби, по умолчанию 1800 (30 минут).
- `maxRooms` — предохранитель, а не правило. Правило — одна комната на игрока.
- `limits.maxConnectionsPerIp` — одновременных соединений с **одного клиента**. Не ставь
  меньше 8: одна загрузка страницы открывает каталог, профиль, комнаты и сводку почти
  одновременно, и маленький кап отдаёт `429` первому же гостю.
- `limits.maxConnectionsTotal` — одновременных соединений на весь сайт: предохранитель,
  чтобы наплыв людей или скрипт не съел память. Это не «сколько людей онлайн»:
  соединение живёт один запрос и закрывается (`Connection: close`), поэтому сотни
  посетителей проходят через 256 спокойно.

## nginx

Готовый блок: [`deploy/nginx-subpath.conf.example`](../deploy/nginx-subpath.conf.example).

```nginx
location = /vlalchillow { return 301 /vlalchillow/; }

location /vlalchillow/ {
    proxy_pass http://127.0.0.1:8080/;   # слэш в конце срезает префикс
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    client_max_body_size 16k;
    proxy_read_timeout 15s;
}
```

`X-Forwarded-For` здесь обязателен и обязан **перезаписываться** (`$remote_addr`, а не
`$proxy_add_x_forwarded_for`). За прокси все соединения приходят с адреса прокси, и без
заголовка панель видит одного клиента вместо всех посетителей: общий лимит частоты и
общий кап соединений выжигает первый же поток людей, после чего `429` получают все,
включая тех, кто только открыл страницу. С заголовком у каждого гостя свой бакет.

Заголовку панель верит только от **своего** отправителя: loopback или приватная сеть
(RFC 1918, ULA, link-local). Запрос, пришедший напрямую из интернета, права назвать себя
чужим адресом не получает: для него клиент это адрес сокета.

**Чего не бывает ни в одной конфигурации:** «сайт лёг для всех». Если адрес посетителя
отличить нельзя (заголовка нет, панель открыта наружу мимо прокси, прокси сам пришёл с
публичного адреса), такой адрес помечается общим, и ему **никогда не включается долгая
пауза**: остаётся только посекундный лимит частоты, который снимается через секунду. Это
гарантия на стороне сервера — от настройки прокси она не зависит. Поэтому `realip` и
подобные надстройки для защиты от `429` не нужны: они нужны только чтобы лимиты считались
по человеку, а не по прокси, и без них сайт остаётся живым.

Если перед прокси стоит ещё и CDN (Cloudflare, туннель), `$remote_addr` это адрес CDN, а
не человека, и все посетители снова сливаются в один бакет. Лечится на стороне прокси, не
в сервере: включи `ngx_http_realip_module` (`set_real_ip_from` с диапазонами CDN плюс
`real_ip_header CF-Connecting-IP`), тогда `$remote_addr` станет настоящим адресом, а
`X-Forwarded-For` корректным.

Проверить и применить:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## Если nginx на другой машине

Самая частая причина 502 при живом сервере: панель слушает `127.0.0.1`, а прокси
стучится на сетевой адрес (например, `192.0.2.10:8080`) — это разные интерфейсы,
соединения не будет.

- `web.bindAddress` должен быть `"0.0.0.0"` (это дефолт, менять не нужно);
- в `proxy_pass` — адрес машины, где запущен сервер:
  `proxy_pass http://192.0.2.10:8080/;`
- `proxy_pass` с путём (`/`) срезает префикс `/vlalchillow/`, панель получает
  `/api/rooms` — так и задумано.

Проверка с машины с nginx, до правки конфига:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' http://192.0.2.10:8080/healthz
```

`200` — сеть в порядке, дело в nginx. Отказ соединения — панель слушает не тот
интерфейс (или не запущена).

При старте сервер сам печатает адреса, по которым панель реально открывается:

```
[web] панель на порту 8080 (комнат до 64, лимит 10 запр/с с IP)
[web]   с телефона (та же сеть): http://192.0.2.10:8080/
[web]   на этой машине:         http://127.0.0.1:8080/
```

## Если открывается 502 Bad Gateway

nginx жив, но за ним никто не слушает. Проверяй по порядку:

1. Запущен ли сервер и что он напечатал на старте:
   ```
   [web] панель на http://127.0.0.1:8080/ ...
   ```
   Если вместо этого `[web] панель НЕ поднялась: ...` — в причине уже написано, что не так.
2. Не занят ли порт старым процессом: `ss -ltnp | grep 8080`.
3. Совпадает ли порт в `proxy_pass` с `web.port`:
   `grep -A3 'location /vlalchillow' /etc/nginx/sites-enabled/*`.
4. Не выключена ли панель: `"enabled": true` в `config.json`.

Панель **не** падает, если занят игровой порт 7777: страница откроется и покажет
предупреждение. Это специально — иначе «сервер не запустился» выглядело бы как
«сайт сломался».

## API

Панель отдаёт JSON — им пользуется её же страница, но можно и своим скриптом.

### `GET /api/status`

```json
{
  "onlineLobby": 2, "onlineMatch": 5, "onlineTotal": 7,
  "roomsCount": 3, "roomsMax": 64, "nextNumber": 4,
  "gameListening": true, "matchRunning": true,
  "mode": "Ranked2v2", "levels": "Sandstone 2x2",
  "serverUtc": "2026-11-14T12:00:00.0000000Z"
}
```

Собирается раз в секунду и отдаётся из кэша: запросы панели никогда не заходят в
горячие блокировки игрового цикла.

### `GET /api/rooms`

```json
{
  "nextNumber": 4, "count": 3, "maxRooms": 64,
  "rooms": [
    { "number": 3, "mode": "Ranked2v2", "modeName": "Союзники",
      "level": "Sandstone 2x2", "name": "вечерняя", "owner": "влал", "ownerId": 47021139,
      "state": "live", "players": 4, "scoreCt": 5, "scoreTr": 3,
      "joinCommand": "/join 2v2 #3",
      "perTeam": 2, "maxPlayers": 4, "teamLabel": "2 на 2",
      "createdUtc": "2026-11-14T11:59:00.0000000Z" }
  ]
}
```

`state` — `waiting` | `live` | `finished`. `scoreCt`/`scoreTr` — счёт команд из
`room.Flow` (столько же, сколько видит матч-хост): панель показывает `scoreCt * scoreTr`
и ничего не досчитывает сама, поэтому счёт в списке не может разойтись с каткой.
`isMine: true` стоит только у комнаты,
чей `ownerId` равен вошедшему игроку, — страница поднимает её наверх пишет
«Моя комната» и показывает «Завершить игру».

### `POST /api/auth`

```json
{ "code": "123456" }
```

Код из лобби. В ответ `200` и кука `sc_session` (`HttpOnly`, `SameSite=Lax`,
`Secure` при `web.secureCookies`); `Set-Cookie` один раз — дальше сессия едет сама.
Код одноразовый: после обмена он мёртв, а сессия живёт до перезапуска сервера.

| Ответ | Когда |
|---|---|
| `200` | Вошли, в теле `player { id, nick, admin, customId, displayId, since }` |

`customId`/`displayId` — что показывать игрокам: кастомный ID, если админ его
поставил, иначе числовой. Внутренние ключи (баны, `admin.ids`, статистика) всегда
остаются числовым `id`.

`GET /api/me` — та же проверка по куке: `401` без сессии, `403` при бане (сессия
при этом гасится). `POST /api/logout` — погасить сессию и снять куку.

### `GET /api/stats/me`

Статистика вошедшего: `{ kills, deaths, kd, seconds, matches, customId, displayId }`.
Без сессии — `401`, при бане — `403`.

### `GET /api/player?q=` — публичный профиль

Открыт всем, без сессии. `q` — числовой или кастомный ID. Ответ:

```json
{
  "ok": true, "id": 25354325, "nick": "влал", "customId": "Vlal2026",
  "displayId": "Vlal2026", "admin": true, "status": "lobby",
  "hasAvatar": false, "banned": false, "lastSeen": "2026-11-18T12:00:00Z",
  "stats": { "kills": 120, "deaths": 80, "kd": 1.5, "seconds": 7200, "matches": 14 },
  "reports": { "total": 1, "open": 1, "accepted": 0, "windowDays": 30 }
}
```

`reports.total` — открытые + подтверждённые за 30 дней, **без отклонённых**. IP и
устройства наружу не отдаются никогда. Неизвестный ID → `404 not_found`, пустой
`q` → `400 bad_query`.

### `GET /api/administration`

Публичный список из живого `admin.ids`: `{ ok, admins: [ { id, nick, customId,
displayId, admin: true, status, hasAvatar, lastSeen, reports } ] }`. Пустой список —
`{"ok":true,"admins":[]}`; пока хост не подключён — `503 not_ready` (пустота не
должна выглядеть как «админов нет»).

### `POST /api/reports` — отправить жалобу

```json
{ "target": "25354325", "category": "cheat", "reason": "стреляет через стену" }
```

Нужна сессия сайта. `target` — числовой или кастомный ID; ник, админ-бейдж и
устройства цели сервер определяет сам, подставить чужого нельзя. `category` —
`cheat` | `teamkill` | `insult` | `spam` | `other`; `reason` — до 500 символов
(пустой допустим). На себя жаловаться нельзя.

| Ответ | Когда |
|---|---|
| `200` | Принята: `{ ok, report, reports }`, `reports` — свежий счётчик цели |
| `400` | `bad_json`, `bad_target`, `bad_category`, `reason_too_long`, `self_report` |
| `401` | `no_auth` |
| `403` | `banned` |
| `404` | `not_found` — такого ID сервер не помнит |
| `409` | `already_reported` — на эту цель от этого автора уже есть жалоба за 24 ч |
| `429` | `cooldown` (20 с между жалобами) или `daily_limit` (5 в сутки); жди `Retry-After` |
| `503` | `reports_disabled`, `reports_storage` — файл не записался, жалоба не принята |

Лимит по IP намеренно не ставится: за одним NAT сидят разные люди. Держат автор и
цель.

### `GET /api/reports/mine?page=`

Свои жалобы, новые сверху: `{ ok, page, pageSize, total, pages, items }`. В `items` —
`id, targetId, targetNick, targetAdmin, reporterId, reporterNick, category,
categoryLabel, reason, status, statusLabel, created, reviewed, reviewedBy,
adminNote`. Без сессии — `401`.

### `reports.json`

Жалобы лежат в `reports.json` рядом с exe, формат версионирован (`"version": 1`).
Запись атомарная (tmp → замена), битый файл откладывается в `reports.json.corrupt.bak`
и хранилище стартует пустым; файл новее сервера читается, но не перезаписывается.
Каждая запись хранит числовой ID цели и ключи устройств (`LB…`, когда сервер их
знает). При следующем входе игрока устройства дописываются в его старые жалобы —
смена ника или VPN не обнуляет историю.

### `GET /api/admin/reports?status=&page=` и `POST /api/admin/reports/status`

Модерация в той же вкладке «Репорты». Тот же тройной затвор, что у остальной
админки: сессия сайта → живой `admin.ids` → админ-кука `sc_admin` этого запуска.

Список: `status` — `open` (по умолчанию), `accepted`, `rejected`, `all`; ответ
`{ ok, status, summary: { open, accepted, rejected }, page, pages, items }`.
Решение:

```json
{ "id": "r-…", "status": "accepted", "note": "необязательно, до 200 символов" }
```

`accepted` — подтвердить, `rejected` — отклонить; отклонённая перестаёт считаться
в бейдже. Повторно разобрать уже разобранную жалобу нельзя → `400 report_not_updated`.

## Админ панель

### `GET /api/avatar`

Аватар вошедшего игрока: ровно те байты, что клиент прислал в лобби, с типом по
magic-байтам (`image/jpeg`, `image/png`, `image/webp`), `Cache-Control:
private, max-age=300`. Аватара нет или формат не распознан — `404`; без сессии
`401`, при бане `403`.

### `GET /api/modes`

Режимы и карты из каталога сервера. Страница берёт список отсюда, а не хранит копию:
копия неизбежно разъехалась бы с `GameModeCatalog`.

### `POST /api/rooms`

```json
{ "mode": "2v2", "level": "Sandstone 2x2", "name": "вечерняя" }
```

`mode` — алиас или id (`2v2`, `Duel`, `tdm`…), `level` и `name` можно опустить.
**Нужна сессия** (сначала `POST /api/auth`).

**Владелец берётся из сессии, а не из тела.** Вписывать свой ID в запрос больше
нельзя: кто ты — сайт узнал при входе по коду, ник для подписи берётся из списка
тех, кто прямо сейчас в лобби. Поля `ownerId`/`owner`, если их пришлют, молча
игнорируются. Ушёл из лобби — комната не создаётся, клиенту говорят «не в сети».

| Ответ | Когда |
|---|---|
| `201` | Комната создана, в теле `joinCommand` |
| `400` | `unknown_mode`, `unknown_level`, `bad_json` |
| `401` | `no_auth` — нет сессии, сначала вход по коду |
| `403` | `banned` — аккаунт забанен |
| `409` | `player_offline` (игрока сессии нет в лобби), `one_room_per_player`, `too_many_rooms` |
| `429` | Слишком часто; смотри `Retry-After` |
| `500` | `room_not_created` — игровая комната не поднялась, запись откатана |
| `503` | `room_limit` — кончились номера комнат |

### `POST /api/rooms/{number}/end`

Закрыть катку досрочно, как `/end`, но с сайта. Нужна сессия, и номер должен
принадлежать вошедшему игроку — чужая комната не закроется никогда.

| Ответ | Когда |
|---|---|
| `200` | Катка закрыта, игроки уходят в лобби |
| `401` | `no_auth` |
| `403` | `not_owner` (чужая комната) или `banned` |
| `404` | `no_room` |
| `409` | `not_ended` — эту катку уже завершили |

Дальше работает обычный «золотой» путь завершения из захвата: `C2=201` FinalHud
со счётом и победившей командой → 5 секунд → `C2=255` → комната закрывается и
номер освобождается. Счёт показывается честный, даже 0:0. |

## Админ панель

Отдельный контур для аккаунтов из `admin.ids` в config.json (файл перечитывается
на ходу — админство включается/выключается без рестарта). Двойной вход: сначала
обычная сессия сайта по коду из лобби, затем код этого запуска — тот же, что админы
вводят в чат лобби; он печатается в консоль и лежит в `auth.txt` рядом с config.json,
живёт до рестарта сервера. После рестарта и код, и админ-сессии умирают — вход заново.

Каждый админ-запрос проходит тройной шлюз: сессия сайта (иначе `401 no_auth`) →
живой список `admin.ids` (иначе `403 not_admin`) → кука `sc_admin` с этим же ID
(иначе `403 no_admin_auth`). Исключение — анонимный `GET /api/admin`: он отдаёт
`200 {ok,admin:false,authed:false}` без данных, чтобы страница поняла, что рисовать.
`GET` на `POST`-роуты → `405` со списком методов.

### `GET /api/admin`

Состояние для страницы: `{ ok, admin, authed, id, nick, customId, bans: { enabled,
minMinutes, maxDays } }`. `bans.minMinutes/maxDays` — границы сроков из config.json
(по умолчанию 10 минут..14 дней), страница рисует по ним подсказку.

### `POST /api/admin/login` / `logout`

```json
{ "code": "…" }   // код из auth.txt этого запуска
```

| Ответ | Когда |
|---|---|
| `200` | Вошли: `{ ok, admin, authed, id, nick, customId, bans }` + кука `sc_admin` |
| `401` | `no_auth` — нет сессии сайта |
| `403` | `not_admin` (аккаунт не в `admin.ids`), `no_admin_auth`, `bad_code` — код не подошёл (он новый после каждого рестарта) |

`logout` гасит админ-сессию, сессия сайта остаётся.

### `GET /api/admin/lookup?id=`

Превью для шага «найти игрока»: `{ ok, id, nick, status: lobby|match|offline,
hasAvatar, banned, customId, lastSeen }`. Игрок ищется по памяти (лобби/катка) и
справочнику банов (все, кто когда-либо заходил). Неизвестный id → `404 not_found`,
`id=0`/мусор → `400 bad_id`.

### `POST /api/admin/customid`

```json
{ "customId": "MoйNick2026" }
```

Свой отображаемый ID: только цифры и английские буквы, 1..24 символа, уникальность
без учёта регистра. Пустая строка/`null` — сброс к числовому. Оригинальный числовой
ID сервер не теряет: баны, `admin.ids` и статистика продолжают работать по нему,
подменяется только то, что видят игроки (в лобби и в катке, со следующего входа).
Значение лежит в `customids.json` рядом с exe — рестарт ничего не теряет.

| Ответ | Когда |
|---|---|
| `200` | Сохранено/сброшено, в теле новое состояние |
| `400` | `bad_custom_id` — не по паттерну, длиннее 24, занято другим админом, «хост не подключён» |

### `POST /api/admin/ban`

```json
{ "id": 12345678, "reason": "читы", "durationValue": 6, "durationUnit": "d" }
```

Срок — число + единица (`m`/`h`/`d`), итоговые минуты обязаны попасть в диапазон
config.json (10м..14д). Цель — по числовому ID; админов (включая себя) и `Server`
банить нельзя, коллизии ID → отказ. Игрок при этом выкидывается из лобби/катки, и
все в лобби видят объявление (кто, кого, срок, причина) — то же, что и у бана
внутриигровыми командами. Запись в `banlist.json` переживает рестарт.

| Ответ | Когда |
|---|---|
| `200` | `{ ok, id, nick, duration, expires, reason }` |
| `400` | `bad_id`, `bad_json`, `ban_refused` (админ/себя/ниже минимума/выше максимума/неизвестный id) |
| `401`/`403` | шлюз |

### `GET /api/admin/bans` и `POST /api/admin/unban`

Список активных: `{ ok, bans: [ { id, nick, reason, bannedBy, created, expires,
duration, remaining, ips } ] }`. Разбан: `{ "id": 12345678 }` → `{ ok, removed }`
(сколько записей снято), в лобби уходит «разбанен <ник>»; нечего снимать →
`404 not_found`. Повторное снятие уже мёртвой записи — тоже `404`.

## Флуд-защита

Паролей нет — вход по одноразовому коду из лобби, «одна кнопка» сохраняется.
Поэтому перебор держат две вещи: код (6 цифр, живёт 30 минут, сгорает после обмена)
и адрес:

- больше **30 запросов в секунду** с одного адреса → `429` с `Retry-After`;
- **5 серий отказов** за 10 секунд → пауза **60 секунд** на этот адрес, но **только
  если посетителя можно отличить** (адрес пришёл от своего прокси). Для общего адреса
  долгой паузы нет никогда — иначе один поток погасил бы сайт для всех;
- серия — это не чаще одного штрафа в секунду, поэтому параллельные ответы одной
  загрузки страницы считаются одним отказом;
- не больше **8 соединений** одновременно с одного адреса, **256** на весь сайт;
- заголовки ≤ 8 KB, тело ≤ 4 KB, запрос целиком ≤ 5 секунд.

Кто есть «адрес», сказано выше про `X-Forwarded-For`: за прокси лимиты считаются по
реальному посетителю, а не по машине с прокси.

Два правила, из-за которых сайт раньше «умирал» на толпе и которых больше нет:

- **параллельные ответы это одна серия, а не пять.** Одна загрузка страницы даёт несколько
  ответов сразу; штраф за серию начисляется не чаще раза в секунду, поэтому один заход
  одного человека не может включить блокировку ни себе, ни соседям по NAT;
- **штатные ответы API не считаются «упорством».** `401` «нет входа» и `404` «нет такой
  комнаты» это обычные ответы анонимного гостя. В счётчик идут только отказы самого
  лимита (`429`), испорченные запросы и `5xx`.

Человек с одним браузером этих чисел не замечает: страница делает два запроса в секунду,
а получив `429`, сама ждёт `Retry-After` и не долбит сервер.

Если игроки жалуются на `429` при живом сайте, первым делом смотри, что стоит в
`X-Forwarded-For`: каждый отказ печатается в консоль сервера строкой `[web] <адрес> отказ
(<причина>)`. Один и тот же адрес у всех значит, что заголовок не доходит и править надо
прокси; разные адреса значит, что дело в самом игроке или за его NAT.

## Ограничения

- Комнаты живут в памяти: перезапуск сервера их закрывает. Это осознанно —
  номер комнаты выдаётся один раз и после рестарта начинается заново с 1.
- Номер комнаты — **наименьший свободный**: открыты #1 и #3, новая получит #2.
  Переиспользуется только номер закрытой комнаты, поэтому `/join 2v2 #3` не может
  указать на две живые катки одновременно.
- Одна комната на игрока (ключ — ID, не ник). Это резерв места, а не потолок.
- Потолок комнаты зависит от размера команд: 1 на 1 — двое, 2 на 2 — четверо,
  6 на 6 — двенадцать, режимы без деления — 16. `maxPlayers` и `teamLabel`
  приходят и в списке, и в ответе создания: по ним страница решает, полна ли комната.
- `players` в панели — число живых людей в комнате, без «серверного» актора. В строке
  списка это число больше не показывается (вместо него счёт); оно остаётся в JSON и
  решает, когда писать «заполнена».
- `"enabled": false` не мешает игре: панель просто не занимает порт, UDP и
  обнаружение работают как обычно.
- Когда пустая комната убирается по `emptyRoomTtlSec`, вместе с ней снимается
  и бронь владельца — игрок может создать комнату снова.
- Сессии сайта живут в памяти, как и комнаты: перезапуск — все вышли. Скользящего
  продления нет: сессия не «доживает» от запроса к запросу, она либо есть, либо её
  убили (выход, бан, рестарт).
- «Завершить игру» нельзя отменить: это тот же путь, что `/end`, — катка закрывается
  сразу, результаты игроки увидят.
